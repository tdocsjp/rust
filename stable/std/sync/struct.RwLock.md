# Struct RwLock（要約）

```rust
pub struct RwLock<T: ?Sized> { /* private fields */ }
```

`RwLock` は読み書きロック (reader-writer lock) です。複数の読み取り側、または単独の書き込み側のいずれかが保護されたデータにアクセスできますが、両方が同時にアクセスすることはできません。

## 複数の読み取り側 vs 単独の書き込み側

- 複数のスレッドが同時に読み取りロックを保持し、ブロックされずにアクセスできる
- 書き込みロックを保持できるスレッドは1つだけで、すべての読み取り側・他の書き込み側をブロックする
- 読み取りが書き込みよりも大幅に多い場合、`Mutex` より効率的

## 主なメソッド

- `read()` — 共有の読み取りアクセスを取得する。書き込み側が誰もロックを保持していなければブロックが解ける
- `write()` — 排他的な書き込みアクセスを取得する。読み取り側・書き込み側のどちらも保持していなければブロックが解ける
- `try_read()` / `try_write()` — ブロックしない版。取得できなければ `WouldBlock` を返す

## ポイズニング

`Mutex` と同様に、排他的な書き込みロックを保持している間にパニックが起きると `RwLock` は「ポイズン」状態になります。重要な点として、**読み取り操作中のパニックはロックをポイズンしません**。ポイズンされたロックは:
- 以降のロック取得をエラーにする
- 復旧後に `clear_poison()` でクリアできる

## Mutex との比較

```
Mutex:   すべてのスレッドが平等に待つ（読み取り側も書き込み側も）
RwLock:  読み取り側は並行に進める。書き込み側だけがすべてのアクセスをブロックする
```

`RwLock` は読み取りが多いワークロードに最適で、`Mutex` はよりシンプルで、書き込みが多い、あるいは混在するアクセスパターンに向いています。

**スレッド安全性の要件**: 保護対象の型 `T` は `Send`（スレッド間で共有可能）と `Sync`（読み取り側による並行アクセスに対して安全）を実装している必要があります。
